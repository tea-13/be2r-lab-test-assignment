# HOV-SG: построение графа HM3DSem

Этот сценарий использует `application/create_graph.py` и `application/visualize_graph.py` исходного HOV-SG. Replica feature map в `make hovsg-demo` — отдельный результат; она не содержит иерархии.

## Запуск на подготовленном компьютере

```bash
make hovsg-graph-demo
```

Открывается авторский PyVista viewer. Оранжевые сферы — этажи; синие — комнаты; цветные облака — объекты; линии — принадлежность. Building-root существует в логической иерархии, но upstream viewer его не рисует. Часть структурных категорий (wall/floor/ceiling и др.) и облака ≤100 точек скрыты штатным фильтром: в этом запуске показано 144 из 683 объектных узлов. Остальные остаются в JSON/PLY. Комнаты названы `room_0`, …, semantic room naming отдельно не запускался. Цветовая шкала Distance относится к геометрии линий, а не к уверенности распознавания.

ЛКМ — вращение, колесо — масштаб, Shift+ЛКМ — панорамирование; Q/закрытие окна — выход (штатное управление PyVista). Внешний [launcher](../scripts/hovsg-graph-view.py) меняет только начальную вертикаль камеры на Y, затем выполняет оригинальный viewer. Алгоритмы, отображаемые узлы и связи не изменены. Поиск текста из Replica GUI здесь не переносился: это авторская визуализация графа.

```bash
# Однократно, только если RGB-D последовательности ещё нет:
make hovsg-render-hm3d
# Повтор построения: новый результат, примерно 13 минут на этом хосте.
make hovsg-build-graph
# Просмотр последнего успешного графа:
make hovsg-graph-demo
```

Для другой уже построенной карты: `HOVSG_GRAPH_DIR=/absolute/path/to/graph make hovsg-graph-demo`.

## Проверенный результат

Штатный `create_graph.py` завершился **exit 0**: 400 693 точки; сохранённые mask features `[694,1024]`; в иерархии **2 этажа, 14 комнат (6+8), 683 объектных сегмента**. С учётом building-root — 700 узлов и 699 иерархических связей. Не все маски включаются в этажи. Число объектов означает число сегментов, а не количество уникальных физических предметов.

Время 793.16 с; max RSS 16 942 056 KiB (~16.16 GiB); raw output ~1.7 GiB. Навигационный граф: 1306 узлов / 1440 рёбер; 4 компоненты размером 1140, 148, 14 и 4 узла. Крупнейшая охватывает оба этажа, межэтажное ребро одно. Изолированные компоненты не исправлялись искусственным соединением. Навигация агента по этому графу не проверена.

Проверены непустые PLY, конечные 1024-D object embeddings, согласованность ссылок этаж/комната/объект, навигационные компоненты. Авторский viewer реально открывался и завершился exit 0; сохранён screenshot. Итоговый shell-wrapper отдельно прошёл с `PYVISTA_OFF_SCREEN=true`; интерактивная проверка автоматизировала только сохранение изображения и закрытие окна. [JSON, конфиг, скриншоты и проверки](../results/hovsg/graph-demo/README.md).

## Данные и окружения

Сцена `00861-GLAQ4DNUx5U` уже скачана в составе публичного HM3D example для OneMap. Её рендер выполняется в существующем `be2r-onemap-env:897abb4` (Habitat-Sim 0.2.4), построение — в `.local/envs/hovsg`. Дополнительные установки, API-ключи и загрузки не требуются на подготовленном хосте.

Используются [авторские позы камеры](../third_party/HOV-SG/hovsg/data/hm3dsem/metadata/poses/00861-GLAQ4DNUx5U.txt): 83 кадра с индексами 0, 50, …, 4100 из 4137. Разрешение 640×480, горизонтальный FOV 90°, глубина PNG uint16 в миллиметрах. Внешний renderer вызывает авторские `load_poses_from_file`, `make_sensor_spec`, `save_obs`; выбирает одну доступную сцену вместо жёстко заданного списка из десяти в upstream generator. SLAM и планирование траектории не добавлены.

Выход рендера: `data/datasets/hovsg-hm3d-example/val/00861-GLAQ4DNUx5U/{rgb,depth,pose}`. Повторный renderer отказывается перезаписывать существующую последовательность. Semantic GT не генерируется и не используется для предсказаний.

## Параметры построения

Штатный [create_graph.py](../third_party/HOV-SG/application/create_graph.py) сам добавляет `split/scene_id` к корню входных данных; передавать путь уже до сцены нельзя. Overrides и локальные пути записаны в [wrapper](../scripts/hovsg-build-graph.sh).

- `main.dataset=hm3dsem`, `main.split=val`, `pipeline.create_graph=True` из штатного config.
- `pipeline.skip_frames=1`: все 83 уже отобранных кадра.
- `pipeline.voxel_size=0.05` вместо 0.02 м для снижения RAM.
- SAM `points_per_batch=8` вместо 144; `points_per_side=12` сохранён.
- Локальные OpenCLIP ViT-H и SAM ViT-H; `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True`.
- Остальные параметры merge, выделения этажей/комнат, классификации и навигационного графа — авторские.

Каждый build создаёт новый `results/hovsg/hm3d-graph-<timestamp>-<pid>/raw/`. Указатель `data/cache/hovsg/graph-demo.txt` обновляется только после успешного завершения. Сырые карты, признаки и подробные логи исключены из Git.

## Что означает результат

Иерархия building → floor → room → object связывает геометрические сегменты и их принадлежность. Отдельный Voronoi-граф описывает предполагаемые пути внутри реконструированной сцены. Эти связи не являются произвольными отношениями «на», «рядом с» или «внутри» между любыми двумя объектами.

Число узлов само по себе не подтверждает качество: возможны фрагменты объектов, ошибки класса, разделения комнат и связности путей. Разреженная последовательность и воксель 5 см отличаются от полного эксперимента статьи. Graph accuracy и ObjectNav SR/SPL в этом сценарии не измеряются. Иерархический разбор языковых запросов через OpenAI API — отдельный, не настроенный режим.

Источники: [Graph.build_graph](../third_party/HOV-SG/hovsg/graph/graph.py), [HM3DSem loader](../third_party/HOV-SG/hovsg/dataloader/hm3dsem.py), [генератор наблюдений](../third_party/HOV-SG/hovsg/data/hm3dsem/gen_hm3dsem_walks_from_poses.py), [viewer](../third_party/HOV-SG/application/visualize_graph.py).

## Проверенный вариант с дополнительным объединением

На той же карте отдельно выполнен `merge_objects_graph=true`. Штатной ветке потребовалось подключение пропущенного импорта во внешнем скрипте. Результат: 683 -> 611 объектных сегментов; связи комнат и объектов и авторский viewer проверены. Открыть этот вариант: `make hovsg-graph-merged`. Исходный граф по `make hovsg-graph-demo` сохранён.

[Сравнение, скриншоты и точная команда повторения](../results/hovsg/merge-check/README.md). Этот проход объединяет только одинаково названные пересекающиеся сегменты внутри комнаты; точность физических экземпляров по GT не измерялась.
